FAN-TOKEN BUBBLE DETECTION - R REPLICATION PACKAGE
================================================

OPTIONAL PAPER PROFILE: this guide covers the earlier monthly/weekly and
forecasting analyses, not the submitted report's default daily workflow.
Use README.txt and Working-paper/Report-alignment.txt for the default project.

Purpose
-------
This standalone folder adapts the ORIGINAL R code and methods of Vriz and Grossi,
"Green bubbles: A four-stage paradigm for detection and propagation", Energy
Economics 154 (2026), 109095, to the existing FRAM fan-token project.
DOI: https://doi.org/10.1016/j.eneco.2025.109095
Repository: https://github.com/GianVriz/Green-Bubbles-A-Four-Stage-Paradigm-for-Detection-and-Propagation
Original archived revision: 88dbf4d6f07c61567ae65c81dbe4df9f5ee52a20.

The project uses R and the actual paper packages (exuber, cpm, bsts, forecast,
urca, vars, multDM, MCS, Metrics). It does not invoke Python. The existing Python
project outside this folder is unchanged. Its inputs and outputs are archived
here for provenance, clearly separated from newly computed R results.

This is a fan-token adaptation, not a claim to reproduce the paper's green-energy
numbers. All variable/sample changes and unavailable sections are documented in
Working-paper/Methodology.txt. In particular, Google Trends and financial-stress
data for the fan-token project were not supplied. No data have been fabricated.

2. RAW DATA, SAMPLE AND PROVENANCE
---------------------------------
The sample is the project's fixed CoinGecko category snapshot dated 2026-09-20:
20 sports/team fan tokens plus BTC, ETH and CHZ benchmarks. The calendar starts
no earlier than 2019-01-01, with unbalanced entry on the first valid token price.
Daily cutoff: 2026-09-19. Currency: USD. Time zone: UTC. These frozen dates are
intentional and are not replaced by the execution date.

Code-and-Data/Raw-data contains every file from the project's data/raw folder:
  - yahoo/*.json: 23 original daily OHLC/volume chart responses;
  - coingecko/fan_token_category_snapshot.json: fixed selection snapshot;
  - coingecko/validation_*.json: all archived cross-source responses;
  - raw_market_data.csv: original flattened provider-data export;
  - sample_registry.csv: eligibility, inclusion and provider identifiers;
  - request_manifest.csv: original request URLs, provider and status;
  - coingecko_validation_prices.csv and collection_summary.json.

All existing clean panels, data-quality files, analysis datasets, source files,
configuration, documentation and output artifacts from the Python project are
retained under Provenance/Legacy-Python. This includes the old cross-source
audit and manual review decisions. Those legacy files are not reported as newly
computed R analysis. The R pipeline uses the archived provider JSON directly;
it uses the legacy clean panel only as an independent validation reference.
The raw archives and copied files are immutable inputs for this replication.

No additional API key, live provider request, or network access is needed for
analysis. This package deliberately reproduces the frozen study rather than
refreshing its sample. Request URLs and original collection source are retained.

original notebook additionally requires the packages listed in its own Libraries
section; the author's image already includes them.

4. EXECUTING THE COMPLETE R WORKFLOW
------------------------------------
From this folder, preferred command:
  bash run_docker.sh

The script mounts only this package at /project, uses the current host user for
file ownership, disables container networking, and runs Rscript run_paper_extensions.R.
It does not require Python, the parent repository or a virtual environment.
It overwrites generated Processed-data, Economic variables, Results and Figures
files while preserving raw archives, original paper material and legacy copies.
To use a deliberately chosen compatible image:
  FAN_TOKEN_R_IMAGE=gianvriz/green_bubbles:latest bash run_docker.sh
Using a different image/version may change numerical results; record the change.

Native R equivalent (from this folder):
  Rscript Code-and-Data/run_paper_extensions.R

The R entry points resolve paths relative to themselves, so they can also be
called using absolute paths from another working directory. For interactive R
work, open FanToken.Rproj, setwd("Code-and-Data"), then source("run_paper_extensions.R").

Stages, in exact execution order:
  1. R/01_process_data.R: parse all archived Yahoo JSON; standardize UTC dates;
     clip the frozen date range; check duplicate prices; create daily calendars;
     flag invalid/missing prices, zero volume and extreme returns; compute
     logs, adjacent-day returns, indexed prices and rolling volatility.
     Existing manual decisions are attached to the extreme-return review.
  2. Produce arithmetic mean monthly/weekly prices and one monthly CSV per asset.
     Unfinished final months/weeks are omitted; initial listing periods may be
     partial and are flagged. Internal missing prices invalidate that period.
  3. R/02_detection.R: monthly exuber RADF, 1,000-draw Monte Carlo critical
     values, BSADF series and 95% date stamps; sequential monthly KS-CPM;
     weekly KS-CPM robustness. Save model objects and detection charts.
  4. R/03_propagation.R: align monthly token/BTC/CHZ benchmark systems; compute
     unit-root diagnostics, Johansen trace tests and conditional VECMs; estimate
     p=1 VAR systems and Granger F-tests. This is benchmark propagation, not FSI.
  5. R/04_forecasting.R: expanding-window one-step ARIMA and BSTS forecasts;
     report 95% intervals, accuracy, DM tests and per-token model confidence sets.
     The original repository BSTS uses AR(1), local level and seasonality(12).
  6. validate_paper_extensions.R: verify sample, keys, calendars, transformations, exact
     input recovery, mean aggregation, package output indexing and forecast data.
  7. R/05_report.R: generate Paper-extensions-summary.txt, paper_extension_status.csv, session information,
     package inventory and SHA-256 file manifest.

Randomness: Monte Carlo seed 4, BSTS seed 9 and MCS seed 5. BSTS uses 1,000 MCMC
draws and SuggestBurn(0.1); MCS uses 5,000 bootstrap replications and alpha=0.15.
Configuration/analysis_config.R is the source of the analysis settings.

5. RENDERING THE PAPER-STYLE NOTEBOOK
-------------------------------------
After the full analysis succeeds:
  bash run_docker.sh render_paper_extensions.R
or natively:
  Rscript Code-and-Data/render_paper_extensions.R

This writes Code-and-Data/Paper-extensions.html, including all token charts and result tables,
using the included outputs without rerunning the model estimation. It updates
MANIFEST_SHA256.csv after rendering. Open Paper-extensions.html in any browser.

To execute all modeling stages while knitting the notebook in native R:
  setwd("Code-and-Data")
  rmarkdown::render("Paper-extensions.Rmd", params=list(regenerate=TRUE))
  source("R/05_report.R")
  write_inventory()
The last two lines refresh checksums after the HTML file is written.

Processed-data/clean_observed_panel.csv: valid observed daily prices only.
Processed-data/monthly_panel.csv and weekly_panel.csv: arithmetic period means,
  period boundaries, coverage flags, log prices and log returns.
Processed-data/*_benchmark_system.csv: aligned inputs to propagation estimates.
Economic variables/*.csv: one monthly input dataset for each of the 23 assets.

Results/Paper-extensions-summary.txt and Working-paper/Paper-extensions-results.txt: generated numeric
  summary and limits; these are the authoritative reported R results.
Results/data_quality.csv, descriptive_statistics.csv, extreme_return_review.csv:
  sample coverage and daily data diagnostics.
Results/psy_test_summary.csv: ADF/SADF/GSADF statistics, 90/95/99% critical values,
  sample sizes, minimum windows, lags and decisions.
Results/psy_bsadf_series.csv: monthly BSADF/BADF, endpoint critical sequences and
  BSADF exceedances. No price or critical sequence is forward-filled.
Results/psy_euphoric_episodes.csv: exuber date stamps, package duration and
  ongoing indicator. These are statistical euphoric episodes, not proof of a
  complete economic bubble. Dates refer to monthly period-start labels.
Results/ks_cpm_change_points.csv: estimated change-point date, first post-change
  month and subsequent detection date. These are distinct concepts.
Results/ks_cpm_segments.csv: distribution regimes and return summaries.
Results/weekly_ks_robustness.csv: weekly change and detection dates.
Results/benchmark_*.csv: declared token/BTC/CHZ Johansen, unit-root, VECM and
  VAR/Granger results. Cointegration interpretation is conditional on I(1).
Results/expanding_window_forecasts.csv and *_forecasts.csv: actual/forecast log
  prices, uncertainty bounds, training size and origin; exponentiated point
  forecasts are labeled median USD predictions.
Results/forecast_accuracy.csv: log/price RMSE and SMAPE, interval coverage and
  per-token test windows. SMAPE columns are percentages; return_pct is 100*dlog.
Results/forecast_dm_tests.csv: one-sided package DM tests against available BSTS.
Results/*_model_confidence_set.txt and .rds: package MCS results per token.
Results/*models.rds: saved R fit objects for inspection.
Results/paper_extension_status.csv: completed, adapted and unavailable optional paper blocks.
Results/validation.txt: executed validation checks, including a final pass count.
Results/sessionInfo.txt, installed_packages.csv: actual runtime and dependencies.
Figures/*_detection.png and *_forecasts.png: R-generated figures for each token.

7. VERIFICATION
---------------
Run numerical/data validation independently:
  bash run_docker.sh validate_paper_extensions.R
or:
  Rscript Code-and-Data/validate_paper_extensions.R

Verify every packaged file against the supplied SHA-256 manifest:
  bash run_docker.sh verify_manifest.R
or:
  Rscript Code-and-Data/verify_manifest.R

Validation includes comparing the R-rebuilt daily data to the frozen legacy
clean panel. It is a consistency check on the shared market inputs, not a test
that the different Python and R statistical methods produce identical results.
The new analysis uses the original R algorithms, so such equality is not expected.
The manifest excludes only itself and the optional installed .R-library tree.
After intentionally editing any source/input, rerun the analysis and HTML render
to update both results and checksums. A checksum verifies file identity, not the
truth of a provider observation.

8. EXPLICIT ADAPTATIONS AND MISSING INPUTS
-----------------------------------------
See Working-paper/Methodology.txt for the complete line-by-line mapping.
Key adaptations required by the new asset/sample:
  - monthly mean fan-token USD prices replace RENIXX euro prices;
  - startup=max(20,round(20% of block length)), rather than fixed 46/200;
  - forecast holdout=min(37,n-36), rather than 73 initial plus 37 test months;
  - explicit finite-sample simulated critical sequences replace implicit cached
    defaults; the original exuber package and date-stamping method are retained;
  - token/BTC/CHZ benchmark propagation is labeled as a different variable system;
  - model rank is tested in the new sample, rather than forcing the paper's r=2;
  - without sentiment data, ARIMA/BSTS form the current two-model comparison set.

Missing fan-token Google Trends data prevent the sentiment density/KS comparison
and the paper's four-model ARIMAX comparison. Missing financial-stress data prevent
its FSI propagation analysis. These limitations are part of the deliverable.
Original green-energy search/stress data are preserved ONLY as original-paper
material and are not mislabeled as fan-token inputs.

Optional ARIMAX code is ready in R/04_forecasting.R. To enable it later, add a
REAL file Code-and-Data/Google Trends/fan_token_search_interest.csv with columns
asset_id,date,search_interest, all modeled tokens/months, YYYY-MM-01 dates and
finite nonnegative values. The header-only schema in Configuration/templates is
not raw data. Values are transformed with log1p. ARIMAX_t1 uses lagged interest;
ARIMAX_t conditions on current-month interest and is a nowcast. Current reported
results do not contain these optional models or a synthetic substitute.

The paper's original simulation appendix and all original sections remain in
Original-paper/Code-and-Data/Code.Rmd. To reproduce that separate green-energy
study, work in Original-paper/Code-and-Data and follow its notebook. Those
simulations have not been rerun as part of the fan-token empirical results.
