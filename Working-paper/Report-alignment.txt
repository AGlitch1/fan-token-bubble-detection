--------------------------------------------------------

not substitutes for a financial-stress index.

Default R alignment
-------------------
1. Daily log adjusted closing prices, not monthly averages, are the analysis
   input. The existing raw archives, 20-token selection, and USD/UTC conventions
   are unchanged. Daily adjusted close equals close in these archived crypto
   responses; validation verifies this rather than assuming it.
2. Every token and all three BTC/ETH/CHZ benchmarks are independently estimated
   through 2026-06-30 and 2026-09-19. No September observation enters the June
   estimation or its Bayesian scaling. Benchmark return correlations are
   reported at both cutoffs; no financial-stress variable is introduced.
3. Recursive statistics use exuber 1.1.0 radf(), the methodology paper's actual
   R implementation, on daily log prices with an intercept and zero lagged
   differences. The submitted PSY minimum window counts price observations;
   exuber's minw counts regression rows. Therefore minw is the submitted
   floor((0.01+1.8/sqrt(n))*n) minus one. The explicit conversion preserves the
   original regression sample and prevents a one-observation porting error.
4. To keep the submitted results comparable, reference values are read from
   Configuration/reported_reference_values.csv, copied from the source code
   underlying the submitted Phase 3. The same interpolation/extrapolation and
   SADF-based endpoint approximation are used. They are clearly labeled
   approximate reference classifications, not bootstrap p-values or matched
   BSADF simulated critical values. No p-value is invented. The original R
   calibration methods remain in the optional paper extension profile.
5. BSADF statistics above the reported endpoint reference must persist for at
   least 30 consecutive days to form a retained interval. Gaps are not bridged,
   adjacent threshold failures are not merged, and prices are not forward-filled.
   Price direction and interval price change accompany the statistical signal.
   A falling price path is not automatically described as an upward bubble.
6. The core methodology paper's cpm::processStream with Kolmogorov-Smirnov is
   retained on daily log returns, ARL0=500, startup=max(30,ceil(20% of valid
   return observations)). ARL0=1000 is included as the methodology chapter's
   sensitivity setting. This deliberately differs from Phase 3's penalized
   return-mean/log-squared-return segmentation. Its change counts and the
   report's 76.8% volatility-shift statistic are not interchangeable.
7. The Bayesian component is a base-R port of the LOCAL ADF model actually
   used in the submitted Phase 3: normal coefficient priors, slope prior SD
   0.5, fixed standardized innovation variance, expected run length 365 days,
   posterior reset probabilities and positive-slope probabilities. It does not
   replace this model with the paper's BSTS price forecast, nor claim the
   proposed normal-inverse-gamma or hierarchical model was fitted. Full-sample
   scaling is repeated independently within each cutoff, and is explicitly
   retrospective, as acknowledged in the submitted limitations.

What is excluded from the default project results
------------------------------------------------
Google Trends, a financial-stress index, sentiment-density analysis, ARIMAX,
ARIMA/BSTS price forecasting, Johansen/VECM and multivariate VAR propagation
are not required to replicate this submitted empirical scope. The R code and
earlier outputs for the additional paper sections are preserved as optional
extensions, accessible via run_paper_extensions.R and Paper-extensions.Rmd.
They are not labeled missing project tasks or used to support report claims.

The proposed wild-bootstrap/BIC/volatility-rescaled/long-memory corrections,
NIG Bayesian return model and hierarchical dynamic logit are recorded as
proposed, not reported as implemented. Adding them would be a substantive
extension rather than the minimal alignment requested here.

they are not forced onto the different KS-CPM model.
